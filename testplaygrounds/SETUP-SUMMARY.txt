🔑 KEY DESIGN DECISIONS
══════════════════════════════════════════════════════════════════════════════

✓ SINGLE SOURCE (now):
  One ALMFx/ module supports both versions via feature gates.
  Simpler maintenance, no duplication.
  
  Use shared helpers: Get-PSVersionInfo, Test-PSVersionRequirement, etc.

✓ OPTIONAL FUTURE SPLIT (when/if needed):
  If codebase warrants: ALMFx-PS5/ and ALMFx-PS7/ both reference ../Shared/
  See: FUTURE-MULTI-VARIANT.md for implementation plan.
  
  Trigger only when:
  - Significant code duplication despite feature gates
  - PS7 features can't be fallback-friendly
  - Separate release cadences needed

✓ SHARED CODEBASE PATTERN:
  All cross-version logic in Shared/ folder.
  Public/Private functions use these helpers.
  Easy to reason about, test, and scale.
